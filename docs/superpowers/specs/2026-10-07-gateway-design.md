# aPush gateway fork

User intent: fork 5hux1n/apush, retain its management, rules, templates and providers; integrate the features previously implemented in the separate PushHub. This is an architectural extension. Explicit user implementation/deployment scope and fewer-tests preference override repeated skill approval gates and broad test expansion.

Use the existing MySQL database and the aPush application only. New tables store hashed scoped sender keys, gateway request ownership/idempotency, and durable delivery tasks referencing existing message records. Add alias/enabled to channels. Original webhook parser and rules still work; both rule-driven and direct sends commit messages and tasks before acknowledging receipt. Workers serialize delivery, retry only temporary failures up to three attempts, recover interrupted tasks, and space enterprise robot calls at least 3100ms per webhook. Queue tasks retain rendered input and rule templates, not channel credentials. Atomic API validation prevents partial target acceptance.

POST /api/send accepts Bearer key and title/message/level/channels; omitted targets use key defaults. GET/POST /SCT<token suffix>.send accepts title/desp. GET /api/messages/:uuid exposes only requests owned by the caller. HTTP202 means persisted, not delivered. Preserve the existing bootstrap key through migration. New administrator endpoints use existing aPush login; key secrets are shown once, channel secrets are redacted and blank edits preserve them. Add a linked gateway page for key and queue management and API documentation; extend existing channel editor for aliases, enabled state, ntfy and webhook headers. Retain all upstream channels; improve outbound timeouts and SMTP certificate validation.
